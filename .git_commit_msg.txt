Fix email open: "UID not found" + slow loading after bridge OOM

The bridge process OOMs on Render (heap limit ~245MB) and restarts. The app
opens emails from its persisted AsyncStorage cache (which survives the
restart), but the fresh IMAP fetch can't find those UIDs -> "Message UID not
found" after a long wait.

Fixes:
- fetchEmail now fetches only HEADER.FIELDS + TEXT (no attachments/full body),
  so opens are fast and the bridge holds far less memory (addresses OOM).
- searchMessages keeps all requested body parts so header+text can be joined.
- Open path: if a cached body is shown, a failed background refresh no longer
  replaces the view with an error; the cached copy is kept.
- fetch timeout lowered to 45s so a stale UID fails fast instead of hanging.
- Detail cache is capped at 50 entries to stop unbounded AsyncStorage growth.
